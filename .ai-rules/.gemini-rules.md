# Gemini AI CLI Logging Rule

## Rule: Comprehensive Change Logging in CHANGELOG.md

### Objective
All changes made through **Gemini AI CLI** must be logged in the project's `CHANGELOG.md` file with both technical and summary descriptions to ensure complete traceability, ease of understanding for all stakeholders, and **complete project context preservation** for future AI chat sessions without requiring re-explanation.

### Project Context
This rule governs a **Gemini AI CLI** project where:
- Multiple team members interact with Google's Gemini AI through CLI commands
- AI model configurations, prompts, and integrations need tracking for audit and optimization
- Changes to AI workflows, model parameters, and API configurations must be documented
- New chat sessions require full context understanding from CHANGELOG.md alone
- Both technical and business stakeholders need to understand AI implementation impacts
- Project state must be reconstructable from changelog history for continuity across sessions

### Requirements

#### 1. CHANGELOG.md Format
All logs **MUST** be added to the project's `CHANGELOG.md` file using standard markdown format with the following structure:

```markdown
# Changelog

## [Unreleased]

### Added
- New AI features or capabilities

### Changed
- Modifications to existing AI functionality

### Fixed
- AI bug fixes and issue resolutions

### Removed
- Deprecated AI features or configurations

## [1.2.3] - 2025-07-18

### Added
- [Summary] Technical description with commands and details
- [Summary] Technical description with commands and details
```

#### 2. Dual Description Format
Every changelog entry **MUST** include both:
- **Summary Description**: Human-readable, non-technical explanation (in square brackets)
- **Technical Description**: Detailed technical specification following the summary

#### 3. Mandatory Entry Fields
Each changelog entry **MUST** contain:
- **Date**: When the change was made
- **Change Category**: Added/Changed/Fixed/Removed
- **Summary**: Plain language description in square brackets
- **Technical Details**: Specific commands, parameters, and affected resources
- **Business Impact**: How this AI change affects users/operations
- **Context Tags**: Hashtags for filtering (e.g., #ai-model #prompts #performance)

#### 4. When to Log
Logging **MUST** be performed when:
- Requested by team members or stakeholders
- Making significant AI configuration changes
- Completing major milestones or projects
- Resolving AI-related issues
- Before sharing project context with new AI chat sessions

### Using CHANGELOG.md for New AI Chat Sessions

#### Quick Context Recovery Process
1. **Read Latest Entries** - Review most recent changelog entries for current activity
2. **Check State Summaries** - Look for weekly/monthly state summary entries
3. **Identify Active Issues** - Find unresolved items in "Fixed" sections
4. **Review Milestones** - Check major version changes and feature additions
5. **Understand Current Config** - Look for most recent configuration changes

#### Essential Context Queries
To understand current Gemini AI project state from CHANGELOG.md:
- Search for `#state-summary` for comprehensive status
- Look for `#ai-model` for model-related changes
- Find `#prompts` for prompt modifications
- Check `#api-configuration` for integration changes
- Review `#milestone` for major project changes

### Best Practices

#### Writing Effective Entries
- **Be Specific**: Include exact commands and parameters used
- **Include Impact**: Always explain business/user impact
- **Use Tags**: Add relevant hashtags for easy searching
- **Be Rollback-Ready**: Include enough detail to reverse changes
- **Keep It Current**: Add entries promptly after making changes

#### Organizing Entries
- **Group Related Changes**: Combine related modifications in single entries
- **Use Consistent Format**: Follow the summary + technical description pattern
- **Date Everything**: Always include dates for tracking
- **Version Appropriately**: Use semantic versioning for major changes

### Compliance

- All team members **MUST** follow this CHANGELOG.md logging rule
- Entries **MUST** be added when requested by stakeholders
- Major changes **MUST** be logged immediately after completion
- Context tags **MUST** be meaningful and searchable
- **New AI chat sessions MUST be able to understand full project context from CHANGELOG.md alone**
